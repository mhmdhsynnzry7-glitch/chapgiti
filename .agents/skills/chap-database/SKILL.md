# CHAP Database Workflow

Normal local Development uses the existing default SQL Server instance and its single persistent `ChapGiti` catalog, including VS Code terminal startup. Protect existing data and leave retired sandboxes untouched. The 2026-11-18 owner approval covered SQL008/009 and EF baseline/catalog adoption on this local database after a verified full backup. Future schema changes require a tracked EF migration and snapshot, SQL review, the standing authorization for the verified local Development database, a verified backup and controlled manual execution. Never apply migrations at startup or run write-based integration tests against this database. Disposable test provisioning needs separate authorization. See `docs/CHAP-MAIN-DEVELOPMENT-ACTIVATION-FA.md`.

1. Read `AGENTS.md`, `docs/ARCHITECTURE.md`, migration runner, affected SQL repositories, schema and backup/deployment notes. Never assume documented schema is identical to live schema.
2. The sole existing operational database is **SQL Server `ChapGiti`**. Do not create a replacement operational DB, drop/reseed data, or repurpose SQLite. EF Core 10.x is now the explicitly approved primary persistence target; DbContext/Fluent mappings and any justified SQL remain in Infrastructure.
3. Classify work as **read-only analysis**, **new additive migration**, **application query**, or **destructive data operation**. A task asking for code changes does not authorize migration execution or real database mutation.
4. Use parameterized queries, correct types (`bigint` for documented monetary fields), explicit transactions, proper constraints and concurrency semantics. Keep migrations checksum-versioned; never edit already-applied `001_initial.sql` or other applied files.
5. Before changing identity tables, map legacy `Customer_Accounts`, `Customer_Registrations`, `Customer_Sessions`, `Admin_Users`, `Admin_Usernames`, `Admin_Sessions` and any newer token/OTP/roles tables. Preserve relationships to Orders, Events, Files, Tickets, Ticket_Messages and Audit_Logs.
6. Store customer PDF bytes in private file storage; database stores metadata/file key. Never copy personal PDF data into public assets or deployment packages.
7. For migration: preserve immutable SQL001-009 and add reviewed EF migrations/snapshots after validated adoption, plus backward-compatibility notes and safe verification queries; **do not apply to operational DB** without explicit approval. For destructive cleanup, first produce table/file inventory, record counts, dependency plan and verified backup; stop for separate explicit approval.
8. Integration tests that insert/update/delete require an isolated disposable SQL database whose identity is confirmed before execution; otherwise test with mocks or read-only checks.
9. Deliver concise impacted tables/queries, migration and rollback considerations, commands actually run, data touched and outstanding risks. Do not publish/deploy/package.
