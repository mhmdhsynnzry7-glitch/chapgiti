# CHAP GITI — چک‌لیست تست پذیرش درخواست تا تولید

این چک‌لیست برای بررسی دستی بعد از پیاده‌سازی و اجرای مهاجرت‌های لازم در محیط Development است. UAT-21 تا UAT-30 مخصوص مرکز اعلان‌های درون‌سایت‌اند و ارسال Push یا SMS به گوشی جزو این فاز نیست. هیچ کدام از موارد به معنی اجرای تست در این گفتگو نیست.

به‌روزرسانی ۲۰۲۶/۱۱/۱۶: تیکت فعال بازنشسته است؛ موارد مربوط به آن برای آرشیو/رد عملیات بازنویسی شده‌اند. موارد ۳۱–۴۲ اصلاحیه، فایل و نشان سفارش را پوشش می‌دهند. مهاجرت‌های ۰۰۸/۰۰۹ در این کار اجرا نشده‌اند؛ تا فعال‌سازیِ مجاز و آزمون SQL مستقل، پذیرش دستی این قابلیت‌های پایدار **NOT RUN / BLOCKED** است. هیچ مرحلهٔ این چک‌لیست به‌تنهایی مجوز پیامک یا تغییر دیتابیس نیست. [قرارداد جاری](ORDER-CORRECTIONS-AND-ATTENTION-FA.md).

| شناسه | سناریو | نتیجه مورد انتظار |
|---|---|---|
| UAT-01 | بازدیدکننده ناشناس محاسبه را باز کند | فرم ورود باز شود. پس از ورود مشتری و تکمیل پروفایل، محاسبه‌گر برآورد همان قطع را نمایش دهد |
| UAT-02 | ارسال درخواست پس از محاسبه | اگر کاربر وارد نیست، به ورود برود و پس از بازگشت مشخصات حفظ شود |
| UAT-03 | ارسال درخواست جدید | در حساب مشتری «در انتظار بررسی» و در صف ادمین «جدید» ظاهر شود |
| UAT-04 | مدیر فقط GET جزئیات را باز کند | اگر صرفاً پیش‌واکشی است هیچ انتقالی صورت نگیرد؛ اقدام صریح «باز کردن برای بررسی» فقط یک‌بار عمل کند |
| UAT-05 | مدیر پیشنهاد قیمت ثبت کند | وضعیت «منتظر تأیید مشتری»؛ قیمت نهایی هنوز تأییدشده نیست |
| UAT-06 | مدیر بدون قیمت پیشنهاد بفرستد | خطای واضح، بدون ثبت ناقص |
| UAT-07 | مشتری پیشنهاد را باز کند | مبلغ، توضیح، شرایط و نسخه پیشنهاد مشخص باشد |
| UAT-08 | مشتری اصلاح پیشنهاد را بخواهد | درخواست با دلیل به بررسی بازگردد؛ پیشنهاد قبلی قابل تأیید نباشد |
| UAT-09 | مشتری نسخه جدید را تأیید کند | مبلغ نهایی ثبت شود، وضعیت «تأییدشده/صف چاپ»، رویداد با تاریخ ثبت شود |
| UAT-10 | مدیر قبل از تأیید مشتری شروع چاپ بزند | سرور عملیات را رد کند |
| UAT-11 | مدیر پس از تأیید شروع چاپ بزند | فقط با تعیین تکلیف اصلاحیه‌ها، وجود فایل معتبرِ لازم و پذیرش آخرین قیمت، وضعیت «در حال چاپ» شود |
| UAT-12 | سفارش دارای صحافی | چاپ ← صحافی ← آماده تحویل ← تحویل‌شده |
| UAT-13 | سفارش فقط چاپ | چاپ ← آماده تحویل ← تحویل‌شده |
| UAT-14 | مشتری پیشنهاد را رد کند | درخواست لغو شود و هیچ مرحله تولید مجاز نباشد |
| UAT-15 | مشتری از سفارش‌های من پیگیری کند | بدون ورود کد و شماره، تایم‌لاین درست دیده شود |
| UAT-16 | URL یا API قدیمی ایجاد تیکت باز شود | فرم ایجاد در دسترس نباشد؛ کاربر احراز‌شده HTTP 410 بگیرد، داده‌ای ساخته نشود و سوابق شخص دیگر قابل دسترس نباشند |
| UAT-17 | یادداشت اجرایی مدیر ثبت شود | در پنل ادمین قابل مشاهده و در پاسخ مشتری ناموجود باشد |
| UAT-18 | قیمت‌ها را مرور کند | مبلغ با جداکننده سه‌رقمی و تومان و بدون تبدیل نادرست نمایش داده شود |
| UAT-19 | ثبت‌نام و بازیابی رمز را چک کند | OTP و ورود با رمز مثل قبل کار کنند، ورود مدیر مستقل بماند |
| UAT-20 | مرورگر موبایل و دسکتاپ | مراحل وضعیت، پیام‌ها و دکمه‌ها درست و قابل استفاده باشند |
| UAT-21 | ثبت درخواست چاپ جدید | مدیر یک اعلان با لینک مستقیم به درخواست می‌بیند؛ پس از رفرش هم باقی است |
| UAT-22 | ارسال پیشنهاد قیمت جدید | فقط مالک درخواست اعلان دریافت کند؛ از اعلان به آخرین نسخه پیشنهاد برسد |
| UAT-23 | درخواست اصلاح/تأیید پیشنهاد توسط مشتری | فقط ادمین اعلان مربوطه دریافت کند؛ retry همان عمل اعلان تکراری نسازد |
| UAT-24 | اعلان تاریخیِ تیکت عمومی باز شود | آرشیو مجاز همان گفتگو باز شود؛ فرم پاسخ و تغییر وضعیت وجود نداشته باشد |
| UAT-25 | ارسال پیام/تغییر وضعیت تیکت قدیمی با API | پس از احراز نقش HTTP 410؛ پیام، وضعیت و اعلان جدیدی ثبت نشود |
| UAT-26 | تغییر وضعیت چاپ و آماده تحویل | مشتری اعلان جدید و لینک جزئیات وضعیت دریافت کند |
| UAT-27 | اعلان خوانده‌شده و خواندن همه | نشان اعلان خوانده‌نشده کم شود و بعد از refresh / login مجدد پایدار بماند |
| UAT-28 | به‌روزرسانی هنگام باز بودن سایت | اعلان با SignalR و در قطع آن polling سبک به‌روز شود؛ تب مخفی درخواست بیهوده نفرستد و اتصال مجدد تکرار نسازد |
| UAT-29 | جداسازی نشست مشتری و مدیر | اعلان‌ها و API هر محیط برای دیگری قابل خواندن/تغییر نباشند |
| UAT-30 | رویداد ناموفق یا درخواست تکراری | عملیات rollback‌شده، کلیک بدون ثبت و retry یک عملیات اعلان نادرست یا تکراری نسازند |
| UAT-31 | خدمت با PDF اجباری/اختیاری ثبت شود | الزام فقط برای خدمت تنظیم‌شده، اعتبارسنجی واقعی PDF در سرور و ثبت اتمیک فایل اولیه/سفارش؛ خدمت اختیاری بدون PDF کار کند |
| UAT-32 | مدیر اصلاح سفارش بخواهد | شرح و تصمیم صریح الزام فایل ثبت شود؛ آمادگی چاپ متوقف و مالک مطلع شود |
| UAT-33 | فایل قدیمی یا نامعتبر برای اصلاح الزامی ارسال شود | فایل قبلی کافی نباشد؛ PDF تازهٔ معتبر فقط از همان سفارش/چرخه پذیرفته شود |
| UAT-34 | مشتری اصلاحیه بفرستد | «در انتظار بازبینی» باشد؛ تا اقدام مدیر چاپ مسدود بماند و مدیر اعلان بگیرد |
| UAT-35 | مدیر اصلاحیه را رد/تأیید کند | رد دلیل بخواهد؛ تاریخچه تغییر نکند؛ پاسخ بعدی چرخهٔ تازه باشد؛ سفارش لغوشده با بازبینی زنده نشود |
| UAT-36 | اصلاحیه یا قیمت جدید ثبت شود | آمادگی قبلی معتبر نماند؛ فقط آخرین اصلاحیه/فایل تأییدشده و آخرین قیمت پذیرفته‌شده مجوز چاپ بدهند؛ PATCH تاریخی هم کنترل شود |
| UAT-37 | منو، فهرست یا اعلان خوانده شود | شمار سفارش دیده‌نشده کم نشود؛ تنها نمایش واقعی جزئیات همان نقش آن را کم کند |
| UAT-38 | فعالیت تازه هم‌زمان با مشاهده برسد | sequence قدیمی رخداد تازه‌تر را دیده‌شده نکند؛ شمار در نشست/ورود جدید پایدار و برای نقش/مالک مستقل باشد |
| UAT-39 | منوی باز/جمع‌شده/موبایل بررسی شود | نشان صفر مخفی، شمار بیش از ۹۹ با 99+، عنوان قابل دسترس و بدون overflow باشد |
| UAT-40 | صفحهٔ تماس با CMS کامل و خالی باز شود | کارت‌ها، tel/mailto و لینک‌های امن مطابق تنظیمات؛ بدون ساخت اطلاعات، فرم تیکت یا حساب اجتماعی جعلی |
| UAT-41 | آرشیو و انتقال‌های اعلان بررسی شوند | سوابق محفوظ و فقط خواندنی؛ support Hub غیرفعال ولی هر دو notification Hub فعال بمانند |
| UAT-42 | دانلود/نمایش PDF با نقش‌های مختلف | مالک و مدیر مجاز، مشتری دیگر ۴۰۴ و مهمان/نقش اشتباه ۴۰۱؛ preview و دانلود sandbox و no-store داشته باشند |

## نتیجه‌گیری

- **PASS:** آزمون دستی مشاهده و نتیجه مورد انتظار تأیید شد.
- **FAIL:** خطا بازتولید شد، شناسه باگ + اسکرین‌شات + مرحله ثبت شود.
- **BLOCKED:** وابستگی مانند Migration اعمال‌نشده، دیتابیس ایزوله یا پیامک در دسترس نیست.
- **NOT RUN:** هنوز تست نشده است.

آمادگی نهایی نیازمند نبود P0/P1 حل‌نشده، تست‌های خودکار مرتبط و موفقیت مسیر UAT-01 تا UAT-42 در محیط مجاز است. آزمون خودکار حافظه‌ایِ این کار، جای تست دستی یا پذیرش موتور SQL نیست.
